# 禅道Max 使用说明

官网: https://murphyyi.com

## 1. 应用简介

禅道Max 是一款**纯 Web 应用**（Go + Vue 3 单二进制，浏览器访问即用）的禅道项目管理系统辅助工具，提供 Bug 管理、需求/任务/用例查询、工时日历与写日志、工时统计、定时任务、MCP AI 接口等能力，帮助团队更高效地管理项目。

## 2. 部署与首次配置

### 2.1 启动

```bash
# 发布包（单二进制，前端已嵌入）
./zentao-max                  # 默认端口 12345，可用 PORT/server.port 修改
# 浏览器访问 http://localhost:12345
```

### 2.2 提供禅道连接（三选一）

应用不再提供初始化引导页，禅道连接凭据通过以下方式之一进入系统：

1. **设置页「连接配置」卡片**（推荐）：以平台账号登录后，在「设置」页填写禅道服务器地址、账号、密码，保存即生效（服务端预检连通性、热更新会话并自动清空业务缓存，无需重启）。
2. **auth.db 加密文件**：部署时放置于进程工作目录 `data/auth.db`（路径解析规则见 README「配置」一节）。
3. **环境变量**：`ZENTAO_MAX_ZENTAO_SERVER / ACCOUNT / PASSWORD`（或无前缀 `ZENTAO_SERVER/...`）。

### 2.3 平台登录

- 打开系统默认展示 **SSO 登录**表单（麒麟统一认证）：输入用户名、密码，获取并填入短信验证码登录。
- 登录页仅提供 SSO 入口；本地管理员账号仅可经 API 登录（脚本/自动化场景）。
- 权限模型：**未登录 = 只读**（可浏览查询），**登录后 = 读写**（可编辑、流转、写日志、管理配置）。

## 3. 主界面布局

1. **左侧导航栏**：各功能模块入口；底部为登录状态区（未登录显示「登录」，已登录显示用户名 + 退出）
2. **顶部栏**：当前页面标题和产品/项目选择器
3. **主内容区**：根据选择的功能模块显示相应内容

## 4. 功能模块使用

### 4.1 产品与项目选择

使用任何查询模块前，先在顶部栏选择**产品**，项目选择器会自动联动加载。产品下拉值异常（如显示原始 ID）时会自动清空自愈，重新选择即可。

### 4.2 Bug 管理

- **查询筛选**：按指派人、状态、时间范围等多维度筛选；列表口径与统计卡片一致（全量 + ID 倒序）
- **详情**：点击标题打开详情弹窗，可跳转禅道原始页面
- **编辑 / 质量字段**：详情弹窗内「编辑 / 质量字段」对话框，可一次性填写包版本（fixedPackageVersion）+ 质量分析四字段（原因分析/建议/落实措施/测试建议）
- **流转**：确认 / 解决 / 关闭 / 激活 / 改派
- **记录工时**：详情弹窗内直接为该 Bug 记录工时日志（日期与消耗预填）
- **导出**：勾选后导出 Excel

### 4.3 需求 / 任务 / 用例查询

- 需求、任务、用例列表与详情查看，支持状态筛选与导出
- 任务详情内可**记录工时**（日期/消耗预填，剩余工时自动联动）

### 4.4 工时日历（EffortCalendar）——写日志主入口

- **日历视图**：按日展示工时日志，点击日期批量记录
- **批量写日志**：弹窗内逐行填写（日期、任务/Bug 对象、工作内容、消耗、剩余），按日期分组提交；未来日期会被禅道拒绝（前端已禁选）
- **导入 Excel**：复刻技能包 zt.py 语义——表头自动定位、日期/对象号归一（`任务#123`、`1.15`、`今天` 均可）、剩余留空按当前剩余自动扣减、台账式去重、提交后回读日历核对
- **日备注同步为工时**：日备注弹窗勾选「同步为工时」并选任务，备注全文作为工作内容挂到该任务
- ⚠️ 红线：剩余=0 会把任务置为完成（弹窗内有提示）；接口成功 ≠ 落库，以回读为准；工时被外部系统同步后只能回禅道网页修改

### 4.5 工时统计

本周/上月等快捷范围 + 执行/用户筛选，每日工时、项目分布图表与明细流水，支持搜索排序。

### 4.6 数据看板

Bug/任务/需求汇总卡片与趋势图表。大实例首次聚合（缓存过期后）可能需要数十秒，超时（90s）会返回已收集的部分数据。

### 4.7 定时任务

cron 定时执行报告任务，支持 webhook 通知（钉钉/企业微信）。

### 4.8 健康检查 / 日志

- **心跳检测**页面：对禅道连通性做实时探针（`/api/healthz`），异常自愈
- **日志**页面：查看服务运行日志（含 trace_id），支持清空

### 4.9 MCP 接口（AI 工具对接）

提供 24 个 MCP 工具，支持 HTTP 与 stdio 两种传输、Token 鉴权、运行时热重载：

| 类别 | 工具 |
|------|------|
| 列表查询（9） | ping / get_products / get_projects / get_executions / get_bugs / get_stories / get_tasks / get_users / get_timelog |
| 详情/个人查询（5） | get_bug_detail（Bug 完整详情）/ get_task_detail（任务详情）/ get_story_detail（需求详情）/ get_my_tasks（我参与的任务）/ get_effort_calendar（指定用户全年工时明细） |
| 基础配置/认证（5） | get_zentao_config（查看连接配置）/ update_zentao_config（更新连接配置并持久化保存）/ test_connection（实时连通性探针）/ send_verify_code + sso_login（麒麟统一认证短信登录两步） |
| 写入（5） | record_effort（写工时日志）、add_bug_comment（Bug 评论）、transition_bug（Bug 流转 confirm/resolve/close/activate/assign）、create_bug（创建 Bug，返回新 ID）、transition_task（任务 start/finish/pause/assign） |

**首次接入自助配置**：stdio 模式（AI 工具子进程）没有 Web UI，AI 可直接引导完成初始化——
先 `get_zentao_config` 确认状态，再 `update_zentao_config` 提供服务器地址/账号/密码
（服务端 5 秒预检连通性、验证登录、加密持久化），成功后所有查询工具立即可用；
连接异常用 `test_connection` 定位。auth.db 解密失效导致的「禅道服务器地址为空」
也可由 AI 通过 `update_zentao_config` 直接修复。

| 模式 | 入口 | 适用场景 |
|------|------|----------|
| **http** | `POST http://host:12345/mcp/{action}` 或 JSON-RPC 2.0（协议版本 `2026-07-28`） | Web 应用、远程调用 |
| **stdio** | `cd backend && make build-mcp` 产物 `zentao-max-mcp` | AI 工具（Claude / Cursor 等）子进程 |

MCP 配置（config.yaml 或环境变量）：

```yaml
mcp:
  enabled: true              # 是否启用（运行时可热改）
  transport: http            # http | stdio | both（由启动入口决定）
  token: ""                  # 鉴权 Token，空表示不鉴权
  read_only: false           # true 时拦截 8 个受控工具（数据写+配置/认证），仅保留查询
  actions: []                # action 白名单，空表示允许全部
```

运行时热重载（无需重启）：

```bash
curl http://localhost:12345/api/v1/mcp/status
curl -X PUT http://localhost:12345/api/v1/mcp/config \
  -H "Content-Type: application/json" -d '{"read_only": true}'
```

> ⚠️ 管理 API 未加额外鉴权，生产环境请配合反向代理或网络隔离；建议为 MCP 配置 token。

### 4.10 设置页

- **软件更新**：显示当前版本，一键检查更新（新版本可下载更新包并应用，重启生效）；支持自建更新服务或 GitHub Releases
- **服务与开机启动**：一键将应用注册为系统服务（macOS launchd / Linux systemd / Windows 计划任务，登录自启），支持启动/停止/重启/卸载；安装时固化当前环境变量与工作目录

- **连接状态 / 检测延迟**：实时探针展示
- **连接配置**：禅道服务器地址/账号/密码热更新（见 2.2）
- **MCP 状态**：当前模式与开关

## 5. 常见操作

- **导出数据**：Bug/需求/任务列表勾选后导出 Excel；详情支持 CSV/PDF
- **打开禅道原始页面**：列表/详情中的标题链接直达禅道对应页面
- **重置筛选**：各查询模块「重置」按钮清空条件

## 6. 系统要求

- **服务端**：任意能运行 Go 交叉编译产物的系统（linux amd64/arm64、windows amd64、darwin arm64），无 CGO 依赖
- **客户端**：现代浏览器（Chrome/Edge/Firefox）
- **禅道版本**：兼容禅道 12+ 开源/企业版 REST API，以及禁用 REST 的受限实例（Session 模式，配置 `realm`）

## 7. 故障排除

### 7.1 禅道接口全部报 50002（「禅道服务器地址为空」）

- **原因**：auth.db 缺失或解密失败（历史版本按机器 hostname 派生密钥，hostname 随网络/VPN 变化导致密钥失效，日志可见 `failed to decrypt auth config`）
- **解决**：新版已改为托管密钥文件（`data/encryption.key`，首次生成后稳定，老文件自动回退解密）；若仍解密失败，登录后在设置页「连接配置」重新保存即可，或让 AI 通过 MCP `update_zentao_config` 直接修复；跨机器搬迁时把 `auth.db` 与 `encryption.key` 一起拷贝

### 7.2 登录后仍提示无权限 / 禅道配置失效

- **原因**：平台未登录（匿名只读）或禅道会话失效
- **解决**：侧边栏底部登录；禅道会话由服务端自动 re-login 重试，短暂限流（30s）后重试

### 7.3 需求列表只有第一页数据

- **原因**：受限实例（biz8.x）分页端点语义问题，pages 2+ 返回空（已知限制）
- **解决**：当前返回第一页全量（每页上限内），等待后续修复

### 7.4 看板/任务页首次加载慢

- **原因**：禅道无产品级任务端点，需跨全部执行遍历；缓存过期后首查耗时数十秒
- **解决**：属已知限制，有 60s/90s 超时门控，返回部分数据；缓存命中后恢复正常

### 7.5 端口被占用

- `PORT=8080 ./zentao-max` 换端口；或 `kill -9 $(lsof -ti :12345)` 清理残留进程后重启
